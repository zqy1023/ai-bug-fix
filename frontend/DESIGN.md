## 令牌与组件

`src/app/tokens.ts` 是执行中的颜色、字体与圆角来源，ThemeProvider 写入 `--wb-*` 并同步 Ant Design 主题。
明暗两套主题共享组件与布局。显式选择持久化为 `localStorage.wb-theme`，否则跟随系统。

保留 React + Vite、Ant Design、CSS Modules 与 TanStack Query。页面复用 PageHeader、Panel、StatBand、
KeyValueList、Banner、StatusBadge；新增 RunProgress 与 VerificationChecklist 统一进度和正式业务判定。

## 四个工作区

1. 执行批次：紧凑统计条、真实关注提示、三项主视图与详细筛选、时间窗口、可展开最近动作的批次行及表格内分页。
2. 批次详情：默认展示任务表格、批次进度、待审批提示与配置侧栏；执行案卷、恢复记录、操作审计保留为页签。
3. 任务工作台：同批次任务队列、服务端阶段导航、修复概览、前后重放对照、验证证据链及元数据侧栏。
   代码改动直接读取归档 diff；执行记录保留输入、输出、Agent 追踪、产物与操作；完整案卷保留全部历史展示。
4. 交付审批：左侧队列、候选身份、正式验证证据与内嵌源码差异。桌面审阅区独立滚动，决策条常驻。
   驳回原因、回修阶段与补充说明在决策条中展开，保留原有原因到执行节点的映射。

## 数据与操作语义

- 所有页面读取现有 `/api/v1`；生产组件没有写入画板中的演示任务或指标。
- 执行完成与业务通过分开。缺少正式 assessment 时显示“未记录业务判定”，不推断通过。
- 验证过期时提示重新验证；完整重放优先读取 verification_report 归档，步骤摘要只作降级来源。
- `prepared` 表示本地候选；`published` 才表示正式交付。批准保留二次确认，系统不会自动合并。
- 操作由后端 actions 控制。审批中的任务与仍在推进的批次分别展示。
- 阶段优先使用服务端 stages，旧数据回退到生成的工作流契约。任务按照现有串行工作流推进。
- 成功、失败、受阻、人工、等待与非活动任务的计数来自后端；分段进度保持总数边界。
