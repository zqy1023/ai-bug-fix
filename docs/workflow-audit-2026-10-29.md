## 2026-10-30：纠正复现准入顺序

旧实现会在模型读取源码前，仅因 msg:None/缺响应触发请求复现，失败即跳过。
这扩大了用户限定的复现场景。现所有任务先执行日志、响应及相关源码分析；
已有证据支持定位和修复时直接继续，不要求先请求、不因缺单号停止。
只有日志无明确错误且 Agent 初步输出 INSUFFICIENT_EVIDENCE、未改源码、未发生模型失败时，
才按原始请求补充复现。捕获的业务栈和初步分析交给后续模型继续分析，最多补充一次。
未复现或缺必要请求输入且原分析仍不足时跳过；环境不可用、执行失败或请求超时记失败。
已有明确错误但业务预期不清晰时继续保留分析缺口，不因该缺口强制请求。
本节替代此前“前置复现未成立即跳过”的宽泛描述；历史审计记录保留原事实。

## 修复的交接缺陷

1. 修复 Agent 的 failure_kind、skip_reason 原先未声明在 LangGraph TypedDict 中，
   子图会丢弃字段，外层投影使用默认空值。现已声明并测试真实子图边界，避免只测函数返回值。
2. code_verdict=PASS 但 coverage=unknown/insufficient 的 MANUAL 结果曾能绕过交付门禁。
   现在代码 PASS 必须覆盖充分、无关键 missing_checks；矛盾输出拒绝交付。
3. 上下文或占位失败后曾误入报告生成，最终用“无工作区/基线不一致”覆盖原故障。
   现在这些准备失败直接收尾，保留真实失败阶段。
4. 最终汇总曾覆盖已有报告，丢失审查和交付事实。现在保留完整报告再补汇总字段。
5. Git 内部锚点拼接完整任务及分支名，长业务类型导致引用无法创建。
   现改为有限可读前缀加身份哈希，保留任务隔离与幂等性。
6. Windows 短暂目录占用导致共享快照发布失败，增加有限重试；
   完整基线发布后残留外壳的清理失败不再推翻成功发布事实。
7. 固定验证命令超时原先只终止 Windows venv 启动器，可能遗留真实采集子进程。
   现在保留 Popen 所有权，超时在父进程仍在时回收其进程树；POSIX 使用独立会话并回收进程组。
   真实子进程延迟写文件的回归测试确认超时后不再产生副作用，超时仍记未验证而非业务通过。
8. 真实框架初始化新建日志被源码完整性检查误判为代码改动。现仅识别根 logs 下
   框架日志器精确命名的新日志并记录 runtime_artifacts；已有文件被修改/删除，
   新增其他文件（包括 logs 下 .py）仍记录 source_mutations 并拒绝执行证据。
   真实子进程测试确认正常日志不阻断验证，边界测试确认日志规则不放过源码改动。

## 提示词迭代及真实评测

通用 diagnosis 规则涵盖连接/超时、身份/限流、响应格式、缺字段/null/类型、
实体与事件缺失、时间/状态/地址映射、批量/分页、框架与环境差异。
规则提供核查依据及处理边界，不按承运商列固定修补答案。

修复 Agent：证明原异常与预期处理依据，完成范围内最小候选，交接影响输入、保留规则和证据缺口。
审查 Agent：独立核对改动范围、原异常正确处理、相关业务是否回退；只读，不替修复方辩护或修改。
平台：提供原始证据、执行回执、版本和权限校验，不用 AST 风险提示直接代替模型业务判断。

ShipmentLink 离线边界测试执行的是归档 before/after 解析函数，未请求官网。
保持 1 条有效事件，仅加入含同样提示文字、但未调用的校验函数：
旧代码返回 1 条事件，新代码返回 NotFound 丢弃事件。
这是构造的相邻输入，证明该条件的行为重叠，不证明官网发生频率。
