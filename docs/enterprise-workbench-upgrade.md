# 企业级 AI 修复工作台升级实施规范

## 目标

在现有 `frontend/`、FastAPI 与 LangGraph 上升级为浅色企业级工作台，并建立可治理的修复知识闭环。不得创建第二套前端入口，不以模拟数据替代真实运行记录，不把尚未实现的接口描述为已可用。

## 交付范围

### 1. 前端工作台

- 统一浅色设计：白色导航与内容面板、浅灰工作区、蓝色主操作、语义化状态色、清晰边界和轻量阴影。
- 保留并完善运行总览、执行记录、执行详情、节点检查器、模型调用审计、审批和人工介入队列。
- 运营指标必须来自后端，显示真实数据、时间范围与统计口径。
- 流程图以服务端持久化步骤记录为状态来源；交互图不能代替工作流状态机。
- 长列表具备筛选、分页、加载、空态、错误态和重试；危险操作提供确认与明确结果。
- 移动端采用可折叠导航与自适应内容区；关键操作保持键盘可达。

### 2. 执行控制面

以服务端为唯一状态权威，维护明确的运行状态机。至少区分排队、运行、等待审批、等待人工、请求停止、已停止、成功、失败和中断。

- 启动请求具备幂等键，重复请求不得创建重复运行。
- 一次工作流轮次最多一个执行实例；轮内修复任务严格串行。
- 同轮内同一运输商的同一个问题只能领取一次自动修复资格。
- 暂停、取消、恢复均是服务端控制操作；取消请求与已终止状态必须区分。
- 恢复前验证检查点、代码快照、外部副作用与审批状态；不允许无条件重跑全图。
- 每次控制操作记录操作者、对象、理由、时间和结果。

### 3. 实时事件

统一版本化运行事件，建议字段包括 `event_id`、`run_id`、`task_id`、`sequence`、`event_type`、`occurred_at`、`payload` 与 `schema_version`。

事件先持久化再推送。SSE 支持重连游标、事件去重、断线后快照对账与轮询兜底。不能把仅存在于进程内存中的事件当作审计事实。

### 4. 知识与经验系统

知识分为四类：

1. **确定性规则**：运输商身份、代码修改边界、安全门禁、异常归一化和去重规则；通过受控代码或版本化规则执行，不依赖向量相似度授权。
2. **已验证修复案例**：异常指纹、适用范围、根因证据、Diff、代码版本、回归结果和审查结论。
3. **项目代码知识**：模块职责、依赖关系、调用链、项目约定、共享代码边界及其对应代码版本。
4. **失败经验**：无效方案、回归失败、审查拒绝、错误假设、重复重试原因和规避条件。

案例建议包含：`case_id`、`fingerprint`、`scope`、`root_cause`、`evidence_refs`、`change_summary`、`validation`、`failed_attempts`、`knowledge_version`、`review_status`、`usage_metrics`。

生命周期：候选案例 → 证据和结构校验 → 回归/审查确认 → 审核发布 → 被后续任务检索 → 依据实际使用反馈调整可信状态。未验证内容必须明确标记为候选，不得作为可信修复方案自动复用。知识必须支持版本、适用范围、失效标记、停用和回滚。

### 5. 知识驱动的 Agent 执行

在根因定位前先做低成本确定性预分析，再执行以下检索顺序：

1. 精确异常指纹、运输商、`biztype` 和代码版本匹配。
2. 已验证案例检索。
3. 项目约束、依赖和历史失败模式检索。
4. 按适用范围、版本匹配、验证状态与相关性排序。
5. 只向 Agent 提供少量相关知识和可追溯证据引用。
6. Agent 必须区分当前事实、历史参考和推断；旧案例不能替代本次运行证据。
7. 记录知识命中、采纳、验证结果以及 Token/耗时变化。

优先采用结构化查询与全文检索；只有实际评估表明语义召回存在明显缺口时才引入向量索引。向量相似度不得决定权限、安全边界或自动发布。

### 6. 效率与质量指标

建立可对照的基线，并按异常类型、复杂度、代码版本与模型配置分组统计：

- 首次修复成功率、回归通过率、人工接管率。
- 根因定位耗时、全流程耗时、每阶段 Token 和模型费用。
- 平均重试次数、重复分析率、读取上下文规模。
- 知识命中率、采纳率、复用成功率、失效率。
- 重复异常拦截率与误合并率。

不得用未定义口径的“AI 提效百分比”作为生产指标。优化策略先以离线回放和受控试运行评估；Agent 不得自行修改生产权限、门禁和模型策略。

### 7. 安全与治理

- 服务端认证、资源级授权与角色权限；隐藏按钮不构成授权。
- 密钥、认证文件、敏感日志和模型输入脱敏。
- 产物通过受控 API 读取，校验路径、资源归属和访问权限。
- 日志、文档、历史知识均视为不可信输入，防范提示注入。
- 代码修复限制在授权工作区；命令执行具备白名单、超时、资源限制与隔离。
- 运行记录、事件、知识和审计记录均有保留策略及清理机制。
- 未审批的共享层变更不得绕过审批；回归阶段只测试，不提交；交付阶段才按授权创建修复分支。

## API 契约目标

在核对现有 API 后增量扩展，保持现有 `/api/v1` 契约兼容。目标资源包括：

- dashboard、incidents、runs、tasks、events、approvals、artifacts
- knowledge cases、knowledge feedback、efficiency metrics、audit logs

每个资源都需要明确的请求/响应模型、错误语义、授权规则、分页、版本和测试。新增端点只有在后端真正实现并通过契约测试后，前端才可依赖。

## 验收清单

- [ ] 前端类型检查和生产构建通过。
- [ ] API 契约测试覆盖成功、错误、权限与状态边界。
- [ ] 重复启动不会创建重复运行；任务严格串行。
- [ ] 停止请求不会伪装成已停止；恢复不会无条件重跑。
- [ ] SSE 断线重连后状态与服务端快照一致。
- [ ] 共享层变更、人工审批与人工介入边界可验证。
- [ ] 回归失败不能标记修复成功；回归环境不会意外提交。
- [ ] 知识只在验证与审核后发布；过期知识可以停用和回滚。
- [ ] 历史案例回放对比知识复用前后的耗时、Token、成功率和人工介入率。
- [ ] 未授权访问、路径穿越、敏感数据泄露与恶意日志输入测试通过。

## 当前分支已落地的功能

- 浅色企业级工作台视觉体系与知识中心导航。
- 修复知识案例列表、搜索、状态筛选、候选登记、发布与停用。
- 知识案例使用现有工作台 SQLite 控制库持久化，并记录知识操作审计。
- 案例发布状态由服务端核验来源执行的回归与审查记录，不接受前端直接指定验证结果。
- 执行详情中的任务可将持久化任务记录沉淀为候选知识；重复提交会复用已有案例。
- `prepare_evidence` 会检索已发布案例，按运输商、`biztype` 与异常文本进行轻量排序，并将最多三个候选传入根因定位上下文。检索失败不会阻断原工作流。

## 尚未完成或尚未验证的边界

- 知识召回目前是确定性轻量排序，不是完整的向量检索、离线评估或知识效果分析系统。
- 候选案例自动生成仍由执行详情中的操作触发；尚未实现工作流结束时无须人工点击的自动沉淀。
- 知识采纳、复用成功率、Token 节省等效果指标尚未形成完整统计。
- 仍需在本地执行 Python 测试、前端类型检查、生产构建、API 集成测试和端到端测试。本次远程提交过程未执行这些测试，因此不能声称构建或生产验收通过。
