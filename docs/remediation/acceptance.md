# 合并前验收

用户授权在验收通过后合并 PR #31。验收基线为 `886248ab387ffa0a93e929317005e3b4ec1c5351`；该提交的 CI #109 通过，但追加的竞争故障注入发现了下列遗漏，已在合并前补齐。

| 验收发现 | 修正 | 验证 |
| --- | --- | --- |
| 文件恢复之后租约被接管，旧补偿仍能覆盖 Task 生命周期 | 补偿生命周期与意图写入复用租约事务校验；恢复控制标记前在全局事务内确认持有者 | 接管者标记不被覆盖，过期持有者明确失败 |
| 过期持有者可重新提交恢复 Checkpoint | 恢复 Checkpoint 也纳入写入租约；完成标记绑定 operation id | 过期恢复没有产生 Checkpoint 写入 |
| 补偿本身失败时未保证释放执行锁和全局槽 | Run/Task/单步失败路径通过 finally 清理租约与锁；移除释放租约之后重复执行的旧补偿 | 后续请求可取得锁，其他 Run 可取得执行槽 |
| 补偿失败的 recovery_required 被当作继续执行 | 持久化 recovery_action=rollback；恢复时先完成补偿，再允许新重试 | 不读取 Checkpoint、不追加派单，旧报告恢复 |
| 单步准备期间退出，尚未保存 step_request，恢复会直接读取缺失字段 | 准备阶段先走补偿分支 | 真实恢复 API 回滚准备状态，不执行模型或步骤 |
| 任务在初次校验后、领取租约前被人工关闭 | 获取租约后重新检查人工关闭标记 | 不启动执行线程，关闭状态保留 |

恢复接口还会在取得租约后重读意图，拒绝恢复已完成操作；单步恢复的状态标记经过租约校验。

新增回归均位于 `tests/test_workflow_remediation.py`。完整测试 XML 与结果汇总位于 `evidence/`。合并必须使用最后通过 CI 的精确 head SHA，防止验收后提交变化被一并合入。

本次授权仅针对项目整改的验收与合并；业务候选分支仍保持独立审批和人工合并规则。
