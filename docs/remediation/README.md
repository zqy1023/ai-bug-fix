## 已落实的行为

1. 修复六处步骤执行租约校验缺失 `store` 参数的故障。全局执行槽覆盖不同 Run、CLI、后台和单步入口；单步继续执行沿用同一租约，避免释放后被其他批次插入。Run 锁不再被 LRU 淘汰后出现两个锁实例。
2. 生命周期优先于旧结果。GET 查询只生成投影，不再修改运行及任务状态；有效租约不会被旧心跳误判。取消请求显示“正在停止”，实际退出后才显示“已停止”。人工关闭会阻止整任务与单步自动恢复。
3. 重试先保存 `retry_intent`、报告/步骤/运行元数据备份与文件移动计划，再提交带 operation id 的 Checkpoint。准备失败补偿；提交回执丢失时核对 marker，避免重复派单；排队失败保留可恢复意图。Run、Task、恢复、单步入口均已接入。批次页提供“恢复未完成重试”。
4. 报告归档有独立持久化移动日志。中途失败或进程退出后可恢复，历史版本不被直接覆盖。Windows 原子替换失败保留旧文件及唯一候选临时文件，取消直接截断目标的降级路径。
5. 源码差异继续使用共享的实际 diff/只读基线口径，排除平台 `final.json` 等文件；新增 helper 被确定性检查拦截，原 CRLF 风格恢复后再验收。独立 Review 加载编码规则，模型不能写 `final.json` 或 `task_summary.md`。
6. 固定 longpaths 克隆参数；本地硬链接和普通复制均失败时保留实际异常链。恢复交付核对远端真实 commit；仅允许空引用创建，或对已驳回候选的已知旧 commit 做 compare-and-swap 替换，不覆盖其他提交。
7. 发布候选后创建独立 `final_approval`，绑定 candidate id 与 commit。批准仅记录决定；驳回保存预设原因、详细原因和回退节点，持久化排队。新候选保留旧审批历史并使旧审批失效。旧审批恢复入口停用，审批不占执行图的等待节点。
8. 修补前冻结 `AcceptanceSpec`，保存原始异常、基线、策略的身份及技术/业务要求。修复方的建议不覆盖原合同。Review 对照原合同、实际源码和执行证据，平台计算最终结果。
9. 默认遇到明确旧框架在模型调用前结束；显式开启旧框架分析时仅只读。保留实际调用归属、当前 carrier 范围、可信 biztype/carrier 和复合任务键。补齐英文时间错误、七位小数秒及 WAF 样例的规则加载回归，保留既有缓存噪声排除规则。
10. 最终审批可打开同页原始异常、Review 与真实代码差异。移除仍残留的固定用户、假切换及空通知入口；任务与批次按后端权限展示关闭/恢复按钮。审计默认显示状态、耗时、结论与关键计数，完整输入输出按需展开。SSE 去重与断线轮询分开处理。
11. Task 子图输入去掉批次任务容器，避免逐任务复制整个队列。历史大产物改用内容引用；大日志原文落归档、步骤只保留计数。StepRecord 将历史 `elapsed_ms` 归一为 `duration_ms`，字段冲突明确失败，未知额外字段仍拒绝。
12. Artifact 预览与下载共用路径门禁，拒绝目录逃逸、数据库、工作区及临时文件，并记录读取审计。CI 从少量定向测试扩展为全量后端、前端状态断言、构建及真实 API 浏览器验证。

## 限制与交付门禁

- 此记录证明本地受控实现与回归，不代表已部署；当前主分支仍须经过人工合并。
- 首次远端全量执行发现测试依赖本机模型名与私有日志库，已为模型桩显式配置测试模型名，并把缓存测试的日志/指标初始化限定为桩边界；缓存路径、写入及哈希仍走真实代码。服务入口缺包时现在能够进入已有降级逻辑。重跑脚本在项目虚拟环境不存在时也会拒绝任何状态操作。
- 模型调用和外部承运商在线验收需要独立的运行证据。已有业务未验证结果保持未验证，不因静态审查、fixture 或成功发布而改成业务通过。
- 多存储恢复采用持久化意图及补偿，不宣称文件、LangGraph、SQLite 与 Git 构成单个 ACID 事务。未完成意图通过恢复入口继续，禁止直接覆盖它发起另一轮重试。
- Worker 失效后读取接口给出恢复提示；接管与写入仍必须重新取得租约。人工关闭的任务不可自动恢复。
- 两个依赖弃用告警不影响回归结果；未通过 CI 的提交不得视为已满足远端门禁。
