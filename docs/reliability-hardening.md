# 可靠性加固变更说明

本分支只包含第一批可从静态代码检查中直接修正的可靠性问题，不代表整个重构计划已全部完成。

## 修改内容

- 工作流步骤显式重跑时不再只按步骤名复用历史成功输出，避免验证/回归结果与最新工作区状态不一致。正常工作流恢复仍应依赖 LangGraph checkpoint。
- 独立验证 callback 现在接收 `normalized_log`，让响应重放逻辑能够取得规范化异常上下文。
- `claim_repair_slot` 在检查未合并修复分支后，实际调用 `ExecutionEligibility`，落实同一 run、biztype、carrier 的单次资格约束。
- `apply_plan` 先校验整个方案的路径和目标状态，拒绝越界、目录目标、重复路径和不满足 create/update 语义的目标，不再静默跳过非法路径。

## 尚需后续处理

- `ExecutionEligibility` 当前文件持久化的并发保证仍限于单进程，需要在部署形态确认后补充跨进程原子锁或数据库唯一约束。
- `apply_plan` 已做全量预检，但文件系统写入阶段尚未提供多文件事务；需要结合临时目录、备份/回滚或原子目录切换继续加固。
- 需要在项目依赖齐全的环境执行单元测试、集成测试及真实准生产回归；本次静态改动未宣称测试通过。
- Git 交付状态核验、审批指纹绑定、持久化 checkpoint 和完整领域状态模型仍在后续批次。

## 验收建议

1. 同一 run 中同一 biztype/carrier 的第二个问题不能再次领取资格。
2. 独立验证器收到 `normalized_log`。
3. 方案含一个非法路径时，预检阶段不应写入任何文件。
4. 修改工作区后显式重跑验证步骤，不应读取旧成功输出。
