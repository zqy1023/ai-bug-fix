# 工作流生产可靠性加固

本说明对应分支上的实际代码改动。主分支不自动合并；部署前应在本地安装依赖、运行测试并完成准生产验证。

## 本次实现

- **执行轮次资格**：资格登记采用跨进程 OS 文件锁、锁内重新读取和原子替换；登记文件损坏时 fail closed。键为 run_id + biztype + carrier，同一轮同一运输商只领取一次资格。
- **重试语义**：新增 retry_prepare 节点统一递增 attempt。修复、检查、验证、回归、审查、审批拒绝等业务失败经统一上限控制；任务图不再对所有节点套用通用异常重试，避免 Git 交付等副作用被自动重复执行。只有日志拉取允许瞬时错误自动重试。
- **持久化恢复**：默认 checkpointer 改为 SQLite，checkpoint 文件位于 runtime 目录；人工审批 interrupt 可在进程重启后从同一 thread/configurable.thread_id 恢复。调用方必须在每次执行/恢复时使用稳定且唯一的 thread_id。
- **独立验证**：将规范化异常传入 Response 重放验证；重放输入通过 JSON 文件传递，不再将日志内容和 carrier 名称拼接到 Python 源码；限制 carrier 路径并检查子进程退出码及结构化结果。
- **确定性安全门禁**：疑似硬编码凭据从审查警告提升为阻断项，必须先修复再重新执行检查。
- **审批审计**：人工审批 interrupt 展示任务、修改文件清单、授权文件和变更方案指纹；恢复时可校验提交的指纹；批准后仍重新执行最终范围门禁。
- **方案落盘**：全量预检后将文件写入同目录暂存文件，替换失败时尝试回滚；路径越界、重复目标、目录目标和 create/update 状态不符会拒绝整份方案。
- **交付分支**：拒绝在已有本地修复分支上叠加新任务，避免将旧任务提交带入新交付；没有创建 MR 或自动合并逻辑。
- **准生产回归**：记录执行前后 Git 工作区状态与本轮修改文件哈希，若测试命令提交或改写工作区文件则回归失败。
- **测试**：增加资格持久化/损坏 fail-closed 测试及重试路由上限测试。

## 部署与验收

1. 安装依赖：`pip install -r requirements.txt`。
2. 确认 runtime 目录可写且在重启后保留；SQLite checkpoint 数据库和 eligibility.json 不得放在临时目录。
3. 工作流每轮使用稳定的 run_id，并将其用作 LangGraph checkpoint 的唯一 thread_id；同一轮恢复时不可更换。
4. 配置固定的准生产回归命令；命令只能测试，不得写回代码、生成未跟踪文件或创建提交。
5. 本地执行 `pytest -q`，再用真实测试仓库验证：重复领取、进程重启恢复审批、审批拒绝回修、失败重试上限、恶意路径、敏感信息阻断、回归工作区被修改时失败、交付分支重复时拒绝。
6. 人工检查 Git diff 与提交范围；确认无密钥、token、生产数据或运行产物后，再由维护者决定是否合并。

## 明确的限制

- 文件锁和 JSON 资格登记适用于共享本地文件系统的部署。多主机多容器若 runtime 目录不是共享且支持可靠文件锁的文件系统，应改用数据库唯一约束/事务式资格表。
- 多文件落盘的回滚是尽力恢复，不等同于文件系统级事务；若回滚本身失败会显式报错并要求人工恢复。
- 本次通过 GitHub API 直接写入分支，当前执行环境没有检出完整仓库运行 Python 测试。因此不宣称测试已通过；请按上方验收步骤在本地验证。
