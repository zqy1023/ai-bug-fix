# 工作流状态与任务工作台修复记录

对应 2026-10-21 架构评审。修改基于当前工作区，保留了原有未提交变更；没有启动真实 Agent 修复、连接实际 Git 远端或重启现有后端。

## 缺陷关闭情况

| 评审项 | 修复 |
| --- | --- |
| F01 未验证结果错误回修 | 增加 `UNVERIFIED` 业务结论；runner 保留步骤声明的合法路由，人工审查模式同样携带未验证确认标识。 |
| F02 分析报告交付后仍运行 | 父图 `task_collect` 在任务子图真正退出时收敛 Task 生命周期；写入运行中的 finalize 记录不再提前标记任务失败。 |
| F03 跨 Run 关闭会话 | 会话按 Run/Task 归属租用；活跃会话不能被淘汰，关闭请求等租用结束后生效；初次执行、恢复和单步执行只释放自身资源。 |
| F04 门禁 KeyError | 两处字典后备取值改成显式分支；无实际变化的声明返回 `PHANTOM_CLAIM` 证据。 |
| F05 Python 文件删除 | 语法阶段只跳过基线和门禁共同确认的删除；默认 py_compile 回归命令排除已删除文件。 |
| F06 前端漏节点 | API 从实际图定义和插件注册表返回阶段；节点轨使用服务端阶段，旧版本回退定义也补齐语法回归。 |
| F07 终态持续计时 | 列表和详情共用开始/结束时间投影；终态缺失时间时前端显示未知，不继续增长。停止/跳过不再被算成运行中的任务。 |
| F08 worker 退出后 Task 未收敛 | 心跳超时与缺失终态报告路径同时收敛活跃 Task/步骤；兼容旧失败 Run，保留已完成任务结论。 |
| F09 lifecycle 错误丢失 | 统一错误投影，空 failure 字典不再遮蔽 lifecycle；Task 详情复用同一诊断，页面直接显示批次异常。 |
| F10 推送确认失败不能恢复 | 推送前锚定提交并保存交付收据；重试验证或重推同一提交；远端不同提交及源码变化仍拒绝覆盖；审批驳回后旧收据归档。 |
| F11 单步丢失原策略 | 从原 Run 元数据恢复推送、审查与尝试次数策略，并恢复门禁证据。 |
| F12 checkpoint 锁不统一 | 按数据库缓存完整 `SqliteSaver`，多个图共享同一连接与同一事务锁。 |

额外处理：源码快照发布遇到短暂权限/占用错误时进行有限重试，持续失败写入 Task 级明确诊断；不会覆盖已存在的基线。不可变基线清单改成覆盖通道，准备阶段重试能够真正清空旧清单。

## 前端操作调整

- 用可搜索、可筛选的任务列表替代大量空列；需要处理的任务优先展示。
- Task 页集中展示状态、当前节点、错误、重试、审批入口，区分任务状态与本轮工作线程状态。
- 失败任务默认进入执行记录；结果与交付使用独立页签。
- 工作流路径、checkpoint 和审计保留为独立页签，不占据任务列表首屏。
- 节点显示可读标题；语法回归可直接定位。窄屏节点轨默认折叠，导航保持横向可读。
- 只展示生命周期允许的批次操作；步骤详情请求失败时提供错误说明和重试加载。

## 验证

1. `python -m pytest -q`：**70 passed**。测试范围通过 pytest.ini 限定为项目 tests，避免收集 runtime 中外部业务仓库的测试。
2. 在 frontend 执行 `npm run build`：**通过**，包含 TypeScript 检查。
3. `tests/frontend_smoke.cjs`：**通过**。覆盖搜索、筛选、失败节点定位、Task 重试、人工报告终态、审批跳转、390px 窄屏和步骤接口错误；无页面 JavaScript 异常。
4. `git diff --check`：通过。

后端回归使用临时目录、真实 LangGraph 子图和临时本地 Git 仓库，涵盖：一个 Task 抛 PermissionError 后后续 Task 继续执行、推送完成后确认失败恢复同一提交，以及并发 checkpoint 读写。没有使用真实远端或业务凭据。

浏览器测试可用 `PLAYWRIGHT_MODULE` 指定本地 Playwright 包。设置 `WORKBENCH_STATIC_UI=1` 后，脚本直接通过浏览器拦截加载 frontend/dist 产物与模拟 API，不需要监听测试端口。Windows 使用系统 Edge 无头模式。

新版本后端需要重启才能加载代码。旧失败记录会在新 API 查询时按已持久化的退出事实进行兼容收敛；这不会恢复或重跑已经停止的业务任务。

Windows 持续占用或 ACL 拒绝仍需要处理实际环境；代码保证有限重试、明确失败原因和 Task 异常隔离，不能凭日志认定某一种系统原因已消除。
